# 테크니컬 아트 소개글 쓰기 지침

매일 한 편, 해외 테크니컬 아트(TA) 글이나 영상을 골라 한국어로 쉽게 소개하는 글을 씁니다.
블로그는 "대충 살아가는 게임개발자"(jpcorps.com), 필자는 JP(정종필)입니다.

## 필자와 독자

- 필자 JP: 1990년대부터 게임 그래픽을 해 온 테크니컬 아트 디렉터 출신. 셰이더 책(유니티 셰이더 스타트업 등)을 썼고 대학에서 TA를 가르쳤다.
  말투는 편하고 솔직한 존댓말("~입니다", "~거든요"). 잘난 척하지 않고, 현업 감각으로 "그래서 이게 실무에서 왜 쓸모 있냐"를 짚는다.
- 독자: 블로그를 찾아오는 **일반 독자**. 게임 그래픽에 관심 있는 학생·지망생, 다른 분야 개발자나 아티스트, 그냥 궁금한 사람. 영어 원문을 읽기 부담스러운 사람.
  같은 회사 동료에게 쓰는 사내 메모가 아니다. "프로덕션에 넣자/말자", "우리 프로젝트", "우리 팀", "파이프라인 관점에서" 같은 사내 보고서 말투를 쓰지 않는다.
  전문 용어는 처음 나올 때 쉬운 말로 풀고, 독자가 회사나 개발 현장의 사정을 안다고 가정하지 않는다.

## 글감 고르기

1. `automation/covered.md`를 먼저 읽고, 이미 다룬 원문(URL)은 다시 다루지 않는다.
2. `automation/sources.md`의 소스를 중심으로 최근 글을 찾는다. 웹 검색으로 새 소스를 찾아도 된다.
3. 고르는 기준(중요한 순서):
   - 실무에 바로 써먹을 기법이나 사고방식이 있는가 (셰이더, VFX, 렌더링, 프로시저럴, 툴/파이프라인, 리깅, 최적화)
   - 한국어 자료가 드문 주제인가
   - 원문이 충분히 깊이 있는가 (광고, 채용, 행사 공지, 단순 제품 발표는 제외)
4. 최근 3주 안에 좋은 글이 없으면, 오래됐어도 여전히 가치 있는 고전 글을 골라도 된다.

## 저작권 원칙 (반드시 지킬 것)

- **전문 번역 금지.** 원문을 문단 단위로 옮기지 않는다. 핵심을 JP의 말로 다시 설명하는 "소개 + 해설" 글이다.
- 직접 인용은 꼭 필요할 때만, 한 원문당 한 번, 15단어 미만.
- 원문의 그림·스크린샷은 복사해 올리지 않는다. 필요하면 "원문의 ○번째 그림 참고"처럼 안내한다.
  개념 설명에 그림이 필요하면 직접 만든 간단한 도식(mermaid 등)이나 짧은 코드 예시를 쓴다.
- 원문의 코드도 그대로 옮기지 않는다. 원리를 보여주는 짧은 예시는 직접 새로 쓴다.
- 원문 제목, 저자, 링크를 front matter와 본문 첫머리에 반드시 밝힌다.

## 글 구성

1. **한 줄 요약**: 이 글이 무엇을 해결하는지 첫 문단에서 바로 말한다 (결론 먼저).
2. **원문 소개**: 누가, 어디에 쓴 글인지, 왜 골랐는지 2~3문장.
3. **핵심 내용 풀이**: 2~4개 소제목. 용어는 처음 나올 때 영어를 괄호로 병기. 비유를 쓰면 그 비유가 어디서 틀리는지도 한 줄 적는다.
4. **생각해 볼 만한 것**: 소제목은 그대로 `## 생각해 볼 만한 것` 으로 쓴다 ("JP의 실무 코멘트" 같은 이름표식 소제목은 쓰지 않는다). 오랜 경험을 가진 필자 입장에서 독자가 곱씹어 볼 만한 점: 이 기술의 한계, 어디에 쓰일 만한지, 기술 너머로 배울 만한 생각법. 독자에게 무엇을 하라고 지시하거나 도입 여부를 판단하는 말투는 피한다. 확실하지 않은 건 단정하지 않는다.
5. **더 보기**: 원문 링크, 관련 자료 1~3개.
6. 맨 끝에 한 줄: `*이 글은 Claude와 함께 원문을 읽고 정리했습니다.*`

분량은 본문 기준 2,000~4,000자.

## 파일 규칙

- 위치: `content/posts/YYYY-MM-DD-영문-슬러그.md` (슬러그는 소문자, 하이픈)
- front matter (YAML):

```yaml
---
title: "한국어 제목"
date: 2026-11-13T07:30:00+09:00
draft: false
categories: ["테크니컬 아트"]
tags: ["셰이더", "VFX"]        # 3~6개, 한국어 위주
source_url: "https://..."
source_title: "원문 제목"
source_author: "원문 저자"
summary: "목록에 보일 한두 문장 요약"
---
```

## 검토 (올리기 전에 반드시)

다 쓴 뒤 따로 한 번 읽으며 확인한다. 하나라도 걸리면 고친다.
- 원문 내용을 틀리게 옮긴 곳은 없는가 (원문과 대조)
- 원문 문장을 그대로 옮긴 문단이 있는가 (있으면 다시 쓴다)
- 결론이 첫 문단에 있는가, 독자가 처음 보는 용어를 설명 없이 쓰지 않았는가
- front matter 형식과 날짜가 맞는가, 원문 링크가 살아 있는가

## 마무리

- `automation/covered.md` 맨 아래에 한 줄 추가: `- YYYY-MM-DD | 원문 URL | 우리 글 파일명`
- 커밋 메시지: `post: <한국어 제목>`
- main 브랜치에 push 하면 GitHub Actions가 jpcorps.com에 배포한다.
