## 바닥에 깔린 그 안개, 어디서 본 것 같죠?

젤다 왕국의 눈물을 하면 지하 세계(깊은 하층부)가 떠오르는 분이 많으실 겁니다.
발아래부터 허리께까지 흰 안개가 가득 차 있고, 걷다 보면 안개가 슬쩍 비켜나는 듯한 그 느낌이요.

사실 비슷한 장면은 최근 1~2년 사이 여러 게임에서 많이 보였습니다.
서양 판타지 RPG의 늪지대, 공포 게임의 복도, 오픈 월드의 새벽 안개 —
모두 "바닥에 깔리는 안개"라는 공통점이 있지요.

그러다 Three.js 커뮤니티 포럼에서 흥미로운 글을 하나 찾았습니다.
2025년 12월, **red-reddington** 이라는 개발자가 게임용으로 최적화된 지면 안개 셰이더를 직접 만들어서 공개한 글인데요.
모바일(6년 된 아이폰 기준)에서도 60프레임이 나오고, 그림자나 Three.js 조명과도 잘 어울린다는 게 특징입니다.

오늘은 이 글을 중심으로, "바닥에 깔리는 안개"를 게임에서 어떻게 만드는지 풀어 보겠습니다.

## 먼저, 게임에서 안개를 표현하는 방법은?

게임에서 안개를 넣는 방식은 크게 세 가지입니다.

**첫째, 거리 안개(Uniform Fog).** 가장 단순한 방식입니다.
카메라에서 멀수록 흐려지는 거지요.
구현이 쉽고 비용도 싸지만, 멀리 있는 높은 산이나 구름도 같이 흐려집니다.
위아래 구분 없이 전부 뿌옇게 되는 게 문제입니다.

**둘째, 볼류메트릭 안개(Volumetric Fog).** 안개 덩어리를 실제 3D 공간에서 계산합니다.
빛이 안개를 통과하며 산란하는 모습까지 흉내 내니 가장 아름답지요.
대신 계산 비용이 꽤 비쌉니다.

**셋째, 높이 안개(Height Fog).** 오늘 주인공입니다.
"Y 좌표가 낮을수록 안개가 짙다" 는 단 하나의 규칙으로 지면 안개를 만듭니다.
볼류메트릭보다 훨씬 싸면서도, 거리 안개와 달리 위아래 구분이 됩니다.

![세 가지 안개 방식 비교: 거리 안개, 높이 안개, FBM 추가](/images/tech-art/ground-fog-shader/fig3_fog_types.png)
*왼쪽부터 거리 안개 / 높이 안개 / 높이 + FBM 노이즈. 가운데부터 지면에만 안개가 깔리기 시작합니다. (직접 그린 도식)*

## 높이 안개의 원리: Y 좌표 하나면 충분

높이 안개의 핵심은 단순합니다.
픽셀의 세계 좌표계 Y값을 보고, 낮으면 짙고 높으면 옅어지는 겁니다.

지수 감쇠(exponential falloff)를 쓰면 자연스럽습니다.

```glsl
// 높이 기반 안개 밀도 (기본형)
float fogDensity(float worldY, float fogTop, float falloff) {
    if (worldY >= fogTop) return 0.0;          // fog top 위는 건너뜀
    return exp(-worldY / falloff);             // 낮을수록 짙어진다
}
```

여기서 `falloff` 는 "몇 미터 올라가면 절반으로 줄어드냐"를 결정합니다.
값이 작을수록 안개가 얇고 낮게 깔리고, 크면 더 높이 올라옵니다.

**early exit**(조기 종료) 도 중요합니다.
fog top 위에 있는 픽셀이라면 안개 계산 전체를 건너뛰는 거지요.
실제 장면에서는 안개 위쪽 하늘에 해당하는 픽셀이 꽤 많기 때문에, 이것만으로도 성능이 눈에 띄게 올라갑니다.

![높이별 안개 밀도 그래프와 단면도](/images/tech-art/ground-fog-shader/fig1_height_density.png)
*왼쪽: 높이(Y)에 따른 안개 밀도 곡선. 오른쪽: 카메라 시점에서 본 단면. fog top 위는 완전히 맑습니다. (직접 그린 도식)*

이것만으로도 그럴듯한 안개가 나옵니다.
하지만 카메라가 멈추면 금방 티가 납니다.
안개가 너무 균일해서 "페인팅" 처럼 보이거든요.
살아있는 느낌이 없습니다.

## FBM 노이즈로 안개를 살려 보기

여기서 **FBM**(Fractional Brownian Motion, 프랙탈 브라운 운동 노이즈) 이 등장합니다.

이름이 무서워 보이지만, 개념은 간단합니다.
"주파수는 두 배, 진폭은 절반인 노이즈를 여러 겹 쌓는다" 는 겁니다.

첫 번째 겹: 굵고 느린 패턴, 진폭 1.0
두 번째 겹: 첫 번째보다 두 배 잔잔한 패턴, 진폭 0.5
세 번째 겹: 더 잔잔함, 진폭 0.25
...이런 식으로 여러 겹(옥타브)을 쌓습니다.

결과물은 "큰 덩어리 위에 잔잔한 떨림이 얹힌" 모양이 됩니다.
구름이나 산을 멀리서 보면 이런 모습이지요.

![FBM 노이즈: 옥타브를 쌓아 자연스러운 패턴 만들기](/images/tech-art/ground-fog-shader/fig2_fbm_octaves.png)
*위부터 1~4번째 옥타브, 맨 아래가 합산. 옥타브를 더할수록 디테일이 쌓입니다. (직접 그린 도식)*

이걸 안개 밀도에 살짝 얹습니다.

```glsl
// FBM 노이즈로 안개 밀도를 흔들기
float fbm(vec3 p) {
    float v = 0.0;
    float a = 0.5;
    for (int i = 0; i < 8; i++) {
        v += a * noise(p);
        p *= 2.0;    // 주파수 두 배
        a *= 0.5;    // 진폭 절반
    }
    return v;
}

// 최종 안개 밀도
float d = fogDensity(worldY, fogTop, falloff);
d *= 0.95 + 0.05 * fbm(worldPos + vec3(time * 0.1, 0.0, 0.0));
```

마지막 줄이 핵심입니다.
기본 밀도에 ±5% 정도만 흔들어 주는 거거든요.
이 작은 흔들림이 "안개가 조용히 흐른다"는 느낌을 만들어 줍니다.

time에 조금씩 더해서 XZ 방향으로 천천히 움직이게 하면,
카메라가 멈춰도 안개가 살아있는 것처럼 보입니다.

8 옥타브를 쓰는 이유도 비슷합니다.
4~5 옥타브만으로도 괜찮아 보이는데, 8 옥타브를 쌓으면 자잘한 패턴까지 더해져서
가까이서 봐도 패턴이 뻔히 보이지 않습니다.
모바일 기준으로 60프레임이 나온다니, 비용 대비 효과가 꽤 괜찮은 셈이지요.

## 번외: 2D 유체 시뮬레이션으로 완전히 다른 접근

앞서 소개한 방식은 셰이더로 "안개처럼 보이게 그리는" 겁니다.
물리적인 계산은 없고, 노이즈 함수로 패턴을 만드는 거지요.

전혀 다른 방식도 있습니다.
yomotsu 라는 개발자가 만든 [인터랙티브 지면 안개 데모](https://yomotsu.github.io/ground-fog/)가 그 예입니다.

이 데모는 2D 격자 위에서 실제로 유체 역학을 계산합니다.
마우스로 클릭하면 안개가 흩어지고, 드래그하면 소용돌이가 생깁니다.
스카이림(Skyrim)의 GroundFog 모드가 이 데모에서 영감을 받았다고 직접 밝혔을 정도입니다.

움직임이 훨씬 자연스럽고 반응도 실감 납니다.
단, 2D 격자를 매 프레임 업데이트해야 하므로 메모리와 CPU/GPU 비용이 셰이더 방식보다 높습니다.
Skyrim 모드 기준으로 약 117미터 반경의 격자를 유지하면서 프레임당 약 0.15~0.2ms 정도를 씁니다.

## 생각해 볼 만한 것

셰이더 방식의 FBM 안개는 사실 "속임수"입니다.
유체 역학은 없고, 노이즈로 흉내 내는 거거든요.
가까이서 오래 보면 반복 패턴이 보일 수 있습니다.

그래서 원문 저자도 time 오프셋과 XZ 이동을 써서 패턴이 반복되는 걸 감추는 데 꽤 공을 들였습니다.
이 종류의 셰이더에서 "속임수 감추기"는 절반 이상의 작업이지요. (...)

한편, 모바일에서 60프레임이 나온다는 점은 의미 있습니다.
볼류메트릭 안개를 쓰고 싶은데 플랫폼 제약이 있다면, 높이 + FBM 조합이 현실적인 차선책이 될 수 있겠지요.

젤다 팀이 왕국의 눈물에서 어떤 방식을 썼는지는 공개하지 않았습니다.
저도 플레이하면서 "이거 어떻게 만든 걸까" 했는데, 닌텐도는 말을 안 해 주더라고요. 하하.
아마 여러 기법을 섞었을 겁니다 — 그쪽 팀이 셰이더에 얼마나 공들이는지 보면요.
