## 셰이더토이에서 본 그 알록달록한 색, 어디서 나올까요?

셰이더토이(Shadertoy) 같은 데서 남들이 만든 셰이더를 구경하다 보면, 프랙털이나 물결무늬에 **무지개 같은 색이 촤르르** 입혀진 작품을 자주 보게 됩니다.
코드를 열어 보면 이상하게도 색 그림(텍스처)은 하나도 안 쓰고, `cos` 가 들어간 한 줄짜리 함수만 덩그러니 있지요.

저도 처음엔 '이 사람들은 색을 손으로 다 계산하나...' 했습니다 (...)

그 한 줄의 원조가 오늘 소개할 글입니다. 셰이더토이를 만든 사람 중 하나이자, 거리 함수(SDF)·절차적 그래픽 쪽에서는 거의 교과서 같은 분인 **이니고 킬레스**(Inigo Quilez, 줄여서 iq)가 자기 사이트에 올린 'Palettes'라는 글입니다.

최신 글은 아닙니다. 꽤 오래된 고전이고, 분량도 짧아요.
그런데 지금도 여기저기서 계속 쓰이고, 막상 한국어로 차근차근 풀어 둔 자료는 잘 안 보이더라고요. 그래서 오늘은 원문의 짧은 설명을 **그림으로 하나하나 그려 가며** 풀어 보겠습니다.

## 먼저, '팔레트'가 왜 필요할까

게임 그래픽에서 색 고민은 크게 두 가지입니다.

첫째, **비슷한 물건을 조금씩 다른 색으로.**
풀잎, 돌멩이, 나무, 언덕... 똑같은 색으로 천 개를 깔아 두면 영 플라스틱 같거든요. 하나하나 살짝 다른 색이어야 자연스럽지요.

둘째, **색이 없는 숫자에 색 입히기.**
높이 지도, 밀도, 온도, 프랙털 계산 결과 같은 건 그냥 0~1 사이 숫자일 뿐이라 그대로 보면 흑백입니다. 여기에 '낮으면 파랑, 높으면 빨강' 같은 색을 붙여야 눈에 들어오지요.

두 경우 모두 필요한 건 똑같습니다. **숫자 하나(t)를 넣으면 색이 하나 나오는 장치.** 이걸 팔레트(palette), 또는 색 띠·그라디언트(gradient)라고 부릅니다.

보통은 그라디언트 텍스처(가로로 긴 색 띠 그림)를 하나 만들어서 t 위치의 색을 읽어 옵니다. 이것도 좋은 방법이지만, 텍스처를 하나 더 만들고 들고 다녀야 하지요.
iq 는 여기서 "그냥 식 하나로 하면 안 되나?" 하고 묻습니다.

## 식은 딱 한 줄입니다

원문의 식은 이렇습니다.

```
color(t) = a + b × cos( 2π × (c × t + d) )
```

여기서 t 는 0~1 사이의 숫자이고, a, b, c, d 는 각각 **빨강·초록·파랑 세 칸짜리 숫자 묶음**입니다.
네 묶음 × 세 칸 = 숫자 열두 개. 이 열두 개만 정하면 팔레트 하나가 끝납니다.

"코사인이라니, 삼각함수는 무겁지 않나요?" 하실 수 있는데, 원문도 바로 그 얘기를 합니다.
삼각함수가 비싸다는 건 흔한 오해이고, GPU 에서는 코사인을 대충 흉내 낸 근사식보다 **진짜 코사인이 훨씬 빠르다**는 거지요. 그러니 마음 놓고 씁니다.

자, 그럼 a, b, c, d 가 각각 무슨 일을 하는지 한 채널(예를 들어 빨강)만 떼어서 봅시다.

![코사인 곡선 하나에서 a, b, c, d 를 바꿨을 때의 모양 변화](/images/tech-art/cosine-palettes/fig1_abcd.png)
*파란 선이 기본(a=0.5, b=0.5, c=1, d=0), 주황 선이 숫자 하나만 바꾼 것. (직접 그림)*

- **a** 는 곡선 전체를 위아래로 올리고 내립니다. 색으로 치면 **전체 밝기**지요.
- **b** 는 출렁이는 폭입니다. 크면 진하고 어두운 데까지 확 오가고, 작으면 밋밋해집니다. **대비**라고 보면 됩니다.
- **c** 는 t 가 0에서 1로 가는 동안 **몇 번 출렁이느냐**입니다. c=2 면 두 번 오르내리지요.
- **d** 는 곡선을 **옆으로 미는** 값입니다(위상이라고 부릅니다).

생각보다 별거 없지요?
고등학교 때 배운 사인·코사인 그래프 이동, 딱 그겁니다.

## 세 채널을 살짝 어긋나게 하면 색이 된다

진짜 재미는 이 곡선을 빨강·초록·파랑에 **하나씩** 쓰고, 셋을 서로 다르게 두는 데서 나옵니다.

원문 첫 번째 예시는 a, b, c 는 셋 다 똑같이 두고 d 만 (0, 0.33, 0.67) 로, 그러니까 **1/3씩 어긋나게** 했습니다.

![빨강·초록·파랑 코사인 곡선이 1/3씩 어긋나 있고, 그 아래 결과 색 띠](/images/tech-art/cosine-palettes/fig2_rainbow.png)
*위: 채널별 곡선. 아래: 세 곡선을 합친 색. 빨강이 내려갈 때 파랑이 올라오고, 그다음 초록이... (직접 그림)*

빨강이 꼭대기에 있을 때 나머지는 아래에 있고, 조금 가면 파랑이 올라오고, 또 조금 가면 초록이 올라옵니다.
이렇게 세 색이 돌아가며 주인공을 하니까 무지개가 됩니다.

d 의 차이를 줄이면 세 채널이 거의 같이 움직여서 색은 덜 변하고 밝기만 크게 변하고, c 를 채널마다 다르게 주면 색이 더 복잡하게 꼬입니다.
원문에는 이런 식으로 숫자만 바꾼 예시가 일곱 개 실려 있어요. 그 숫자를 그대로 넣어서 그려 보면 이렇습니다.

![원문 표의 숫자 일곱 세트를 그대로 넣어 그린 색 띠 일곱 개](/images/tech-art/cosine-palettes/fig3_examples.png)
*원문 예시 숫자 1~7번을 넣어 직접 그린 띠. 무지개, 낮과 밤 하늘, 노을빛, 수박색까지 전부 같은 식이다. (숫자 출처: [원문](https://iquilezles.org/articles/palettes), 그림은 직접 그림)*

몇 개만 짚어 보면,

- 2번은 d 를 (0, 0.1, 0.2) 로 조금만 어긋나게 해서, 크림색 → 갈색 → 검정 → 남색 → 하늘색으로 **하늘의 하루**처럼 흐릅니다.
- 6번은 c 가 (2, 1, 0) 입니다. 파랑은 c=0 이라 아예 안 움직이고, 빨강은 두 번 출렁이지요. 그래서 분홍과 노랑이 번갈아 나오는 묘한 띠가 됩니다.
- 7번은 a 와 b 까지 채널마다 다르게 줘서, 전체 색감이 따뜻한 쪽으로 쏠렸습니다.

숫자 열두 개로 이 정도면, 텍스처 한 장 들고 다니는 것보다 확실히 가볍지요.

## 그래서 어디에 쓰나

원문이 꼽는 쓰임새는 앞에서 말한 두 가지입니다.

### 색 없는 숫자에 색 입히기

흑백 노이즈 같은 값을 그대로 t 에 넣어 보면 이렇게 됩니다.

![흑백 노이즈, 무지개 팔레트를 입힌 것, 7번 팔레트를 입힌 것](/images/tech-art/cosine-palettes/fig4_colorize.png)
*같은 흑백 값에 팔레트만 바꿔 입혔다. 높이 지도나 밀도 같은 데이터 확인용으로도 좋다. (직접 그림)*

프랙털 작품에 무지개가 촤르르 입혀진 게 바로 이 방식입니다.
게임 쪽에서는 디버그용 시각화(이 영역의 값이 얼마인지 색으로 보기)에도 손쉽게 쓸 수 있지요.

### 비슷한 물건을 조금씩 다르게

원문이 강조하는 또 하나의 요령이 있습니다.
팔레트 색을 그대로 쓰는 게 아니라, 물건의 **원래 색에 더하거나 곱하라**는 겁니다.
그러면 굳이 HSV(색상·채도·명도)로 바꿨다가 색상을 돌렸다가 다시 RGB로 되돌리는 번거로운 일을 안 해도 된다고요.

풀잎으로 흉내를 내 봤습니다.
풀잎마다 0~1 사이의 아무 번호를 하나씩 주고, 그 번호를 t 로 넣어 나온 색을 바탕 초록색에 곱했습니다. 이때 팔레트는 a 를 크게(0.85 근처), b 를 작게 잡아서 **1 근처에서 살짝만 흔들리는** 얌전한 팔레트로 골랐습니다.

![같은 초록 풀잎과, 바탕색에 팔레트를 곱해 풀잎마다 색을 살짝 바꾼 풀숲 비교](/images/tech-art/cosine-palettes/fig5_grass.png)
*왼쪽은 전부 같은 색, 오른쪽은 풀잎마다 t 를 다르게 넣은 것. 팔레트 숫자는 원문 예시가 아니라 제가 고른 값이다. (직접 그림)*

오른쪽이 좀 더 풀숲 같지요?
누렇게 바랜 잎, 짙은 잎이 섞이니까 덜 플라스틱 같아 보입니다. 이게 원문이 말하는 '바탕색에 곱해서 변화 주기'입니다.

## 셰이더 코드로는

원문에는 GLSL 한 줄짜리 함수가 실려 있습니다. 같은 식을 유니티 쪽 HLSL 로 제가 직접 써 보면 이렇습니다.

```hlsl
// 코사인 팔레트: t(0~1) 하나를 넣으면 색이 나온다
float3 CosPalette(float t, float3 a, float3 b, float3 c, float3 d)
{
    return a + b * cos(6.2831853 * (c * t + d));
}

float4 frag(float4 pos : SV_Position, float2 uv : TEXCOORD0) : SV_Target
{
    // 원문 예시 1번(무지개) 숫자
    float3 col = CosPalette(uv.x,
        float3(0.5, 0.5, 0.5), float3(0.5, 0.5, 0.5),
        float3(1.0, 1.0, 1.0), float3(0.0, 0.33, 0.67));
    return float4(col, 1.0);
}
```

`6.2831853` 은 2π 입니다.
이 코드는 유니티 에디터가 아니라 `glslangValidator` 로 HLSL 컴파일이 되는지만 확인했고, 위 그림들은 똑같은 식을 파이썬으로 계산해서 그렸습니다. 그림 만든 코드는 [make_figures.py](/images/tech-art/cosine-palettes/make_figures.py) 에 있습니다.

셰이더 그래프나 언리얼 머티리얼처럼 노드로 만드는 경우에도 곱하기, 더하기, 코사인 노드 몇 개면 그대로 옮길 수 있습니다.
a, b, c, d 를 머티리얼 파라미터로 빼 두면, 아티스트가 숫자를 만지며 색을 고를 수 있지요. 원문에도 숫자를 바꿔 가며 바로 볼 수 있는 실시간 데모가 연결돼 있습니다.

### 작은 함정 하나: 반복할 때 이음매

t 가 1을 넘어가서 0으로 돌아오는 식으로 팔레트를 **반복해서** 쓸 때가 있습니다(시간에 따라 색이 계속 돌게 한다든지요).
원문은 이럴 때 c 를 **정수**로 두면 끝과 처음이 매끈하게 이어진다고 말합니다. 코사인이 딱 한 바퀴, 두 바퀴를 채우고 끝나니까 당연하지요.

![c=1 은 세 번 이어 붙여도 매끈하고, c=0.7 은 이어 붙인 자리에서 색이 툭 끊긴다](/images/tech-art/cosine-palettes/fig6_seam.png)
*같은 무지개 팔레트를 세 번 이어 붙였다. c 가 정수가 아니면 띠 끝과 처음이 다른 색이라 경계가 보인다. (직접 그림)*

c 를 0.7 처럼 애매하게 두면 한 바퀴를 다 못 돌고 끝나서, 이어 붙인 자리마다 색이 갑자기 바뀝니다.
한 번만 쓰는 팔레트라면 상관없지만, 돌려 쓸 생각이면 기억해 둘 만하지요.

## 생각해 볼 만한 것

**정확한 색을 맞추기는 어렵습니다.**
코사인 세 개로 만드는 띠라서, "이 위치에 정확히 이 빨강, 저 위치에 정확히 이 파랑" 같은 주문에는 약합니다. 아트 디렉터가 색 견본을 콕 집어 준 경우라면 그라디언트 텍스처가 훨씬 속 편할 수 있어요. 코사인 팔레트는 **'대충 이런 느낌의 흐름'을 싸게** 얻는 도구라고 보는 게 맞을 것 같습니다.

**숫자로 색을 고르는 건 생각보다 감이 안 옵니다.**
d 를 0.1 바꾸면 어떻게 될지 머릿속으로 그려지는 사람은 별로 없을 겁니다. 저도 그렇고요 (...) 그래서 실제로 쓸 땐 원문 데모처럼 숫자를 만지면서 바로 보는 환경이 거의 필수입니다. 툴을 만드는 입장이라면, 이 열두 개를 슬라이더로 빼 주는 것만으로도 아티스트에게 꽤 쓸 만한 장난감이 됩니다.

**같은 숫자라도 엔진 설정에 따라 다르게 보일 수 있습니다.**
셰이더토이에서는 계산한 값이 거의 그대로 화면에 나가지만, 엔진이 선형 색 공간(Linear)으로 계산한 뒤 화면용으로 바꿔 주는 설정이라면 같은 숫자가 더 밝고 물빠진 느낌으로 보일 수 있습니다. 남의 예시 숫자를 가져왔는데 색이 이상하다 싶으면 이쪽을 먼저 의심해 볼 만합니다.

**그리고 제일 마음에 드는 점.**
이 글은 엄청난 신기술이 아닙니다. 고등학교 수학 한 줄이에요. 그런데 이 한 줄이 수많은 셰이더에 복사돼 퍼졌습니다.
"텍스처를 하나 더 만들까?" 하기 전에 "이거 식 하나로 안 되나?" 하고 한 번 물어보는 습관, 그게 이 글에서 진짜 배울 점이 아닐까 싶습니다.
대충 살아가는 게임개발자에게 딱 맞는 태도이기도 하고요. 하하.
